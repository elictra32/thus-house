## 4. วิธีทำงาน/สื่อสารที่ชอบ

- คุย**ภาษาไทย** อธิบายง่ายๆ ไม่ใช้ศัพท์เทคนิคเกินจำเป็น
- **งานดีไซน์ → ส่งภาพตัวอย่าง (จอคอม + มือถือ, สว่าง + มืด) ก่อน deploy** แล้วรอคำตอบ
- คำที่แปลว่าให้ขึ้นเว็บจริง: **"deploy ได้" · "จัดไป" · "ลุย" · "อะลองดู"**
- บอกขั้นตอนในหน้า dashboard ภายนอก (GoDaddy / Brevo / Supabase / Vercel) เป็นข้อๆ ตามชื่อปุ่มจริง — เจ้าของจะส่งภาพหน้าจอมาเมื่อหาไม่เจอ
- เจ้าของมักส่งคำขอหลายเรื่องในข้อความเดียว และอาจส่งข้อความแทรกระหว่างทำงาน → ทำให้ครบทุกข้อ และเปลี่ยนตามข้อความล่าสุด
- ถ้าไม่ชอบระหว่างทาง จะบอกตรงๆ ("ไม่ๆ", "ไม่เอาละ") → หยุด ย้อนสิ่งที่ไม่ต้องการ ทำเฉพาะที่ขอ
- หลัง merge ให้เช็กว่า deploy ขึ้น (READY) แล้วรายงานสั้นๆ
- บอกข้อจำกัดตามจริง และเสนอทางเลือกพร้อมค่าใช้จ่าย

- ✓ ส่งอีเมล: เลือกผู้รับได้ — ทดสอบหาตัวเอง / เลือกรายคน / คอร์ส / Role / สถานะ / ทุกคน
