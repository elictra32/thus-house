## 4. วิธีทำงาน/สื่อสารที่ชอบ

- คุย**ภาษาไทย** อธิบายง่ายๆ ไม่ใช้ศัพท์เทคนิคเกินจำเป็น
- **Claude ตัดสินใจเองว่างานไหนต้องทำภาพตัวอย่าง** (เจ้าของมอบให้คิดเอง — ประหยัดเครดิตคลาวด์):
  - **ทำภาพ:** หน้าตาเปลี่ยนชัด / ของใหม่ที่สมาชิกเห็น (หน้าใหม่, layout, สี, การ์ด, ฟอร์มใหม่) → จอคอม + มือถือ ส่งก่อน deploy รอ "จัดไป"
  - **ไม่ต้องทำภาพ:** แก้บั๊ก, หลังบ้าน (API/DB/แจ้งเตือน/Discord/cron), แก้ข้อความ, เพิ่มปุ่ม/คอลัมน์เล็กใน Admin → ทดสอบด้วยโค้ด/เบราว์เซอร์แบบไม่ถ่ายภาพ แล้วอธิบายเป็นข้อความ
  - ไม่แน่ใจ → ถ่ายเฉพาะจุดที่เปลี่ยน 1–2 ภาพ ไม่ต้องครบทุกขนาด
- คำที่แปลว่าให้ขึ้นเว็บจริง: **"deploy ได้" · "จัดไป" · "ลุย" · "อะลองดู"**
- บอกขั้นตอนในหน้า dashboard ภายนอก (GoDaddy / Brevo / Supabase / Vercel) เป็นข้อๆ ตามชื่อปุ่มจริง — เจ้าของจะส่งภาพหน้าจอมาเมื่อหาไม่เจอ
- เจ้าของมักส่งคำขอหลายเรื่องในข้อความเดียว และอาจส่งข้อความแทรกระหว่างทำงาน → ทำให้ครบทุกข้อ และเปลี่ยนตามข้อความล่าสุด
- ถ้าไม่ชอบระหว่างทาง จะบอกตรงๆ ("ไม่ๆ", "ไม่เอาละ") → หยุด ย้อนสิ่งที่ไม่ต้องการ ทำเฉพาะที่ขอ
- หลัง merge ให้เช็กว่า deploy ขึ้น (READY) แล้วรายงานสั้นๆ
- บอกข้อจำกัดตามจริง และเสนอทางเลือกพร้อมค่าใช้จ่าย
- **อยากรู้ว่าปรับอะไรไปบ้าง** → สรุปเป็นตาราง "ปรับอะไร / ได้อะไร" ทุกครั้ง
- ชอบ**แจ้งเตือนสีส้ม** (badge ตัวเลข) และอยากรู้ทุกอย่างสำคัญผ่าน **Discord** โดยไม่ต้องล็อกอิน
- งานแก้บั๊กที่เจ้าของรายงานมาเอง → แก้แล้วขึ้นเว็บได้เลย (ทดสอบในเบราว์เซอร์ก่อน) · ฟีเจอร์ใหม่/ดีไซน์ → ส่งภาพก่อน รอ "จัดไป"
- ถามเรื่องค่าใช้จ่ายบ่อย → ตอบเป็นตาราง ฟรีได้ถึงไหน / จ่ายเมื่อไร / เท่าไร (บาท)
- **Google Drive:** ก่อนเปิด/อ่าน/ค้นไฟล์ใดใน Drive ของเจ้าของ **ต้องขออนุญาตก่อนทุกครั้ง** โดยบอกชื่อไฟล์และเหตุผล (ขอแล้วครั้งหนึ่งไม่นับรวมไฟล์อื่น) · ห้ามลบ/แก้/แชร์ไฟล์ใน Drive เองโดยไม่ได้สั่ง
